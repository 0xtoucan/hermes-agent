# Sandbox SDK coverage survey

What this file is: a **point-in-time survey (2026-09-18)** of the 18 desktop plugins that went through the remote-tier sandbox review sweep — what each one imports from `@hermes/plugin-sdk`, which `host.*` members and gateway methods it touches, what its `plugin.yaml` declares under `desktop_capabilities:`, and how it behaved inside the `<iframe sandbox="allow-scripts">` realm (`loader.ts` / `realm.ts` / `methods.ts`). It documents coverage of the bridge at the time of the sweep; it is not a contract and it is not kept current automatically — see *How to regenerate*.

Trust tiers (see `../runtime-loader.ts`, `pluginTrust`): `bundled` (in-repo `src/plugins/*`) and `local` (a hand-copied folder under `<hermes home>/desktop-plugins/` with no install marker) run in the renderer realm with the full SDK; `remote` (anything installed from the catalog or a git URL — the `.hermes-package.json` marker carries `catalogName`, `repo`, or `sidecarUnreadable`) runs in the sandbox surveyed here.

## Supported surface

Every guest call is one row in `methods.ts`, named with the ONE capability that admits it. Grouped by capability (the four defaults every plugin gets are marked):

- **`ui`** (default) — `register` / `unregister` (contributions; `render` becomes a `SandboxSlot` the host mounts and the frame paints), `notify` (text only: `message`, `title`, `detail`, `kind`), `notifyError`, `haptic`, `paneVisibility`, `openWorkspace` / `closeWorkspace`. `host.state.*` atoms are mirrored into the frame read-only.
- **`storage`** (default) — `storageSet` / `storageRemove`; reads come from a host-fed cache, so `ctx.storage.get` stays synchronous.
- **`events`** (default) — `onEvent` / `offEvent` (`ctx.onEvent`, `host.onEvent`) and `socketOpen` / `socketClose` (`ctx.socket`: the host owns the WebSocket and relays parsed frames).
- **`rest`** (default) — `rest` (`ctx.rest`, the plugin's own `/api/plugins/<id>/` namespace).
- **`rest:any`** — `restAny` (`ctx.restAny`, any `/api/` route).
- **`gateway:request`** — `request` for the read-only allowlist: `billing.state`, `commands.catalog`, `cron.list`, `free_tier.status`, `profiles.list`, `session.history`, `session.info`, `session.list`, `skills.list`, `status`. Exact names only (`GATEWAY_METHOD_CAPABILITIES` in `capabilities.ts`); `host.getGateway().request` routes through the same table. Note `session.history` returns full transcripts — a manifest asking for `gateway:request` should be read as read access to every conversation.
- **`prompt:submit`** — `request('prompt.submit')`.
- **`llm`** — `request('llm.oneshot')` (a third `timeoutMs` argument may lengthen one call, capped at 5 minutes).
- **`composer`** — `composerGetText` / `composerInsertText(text, mode?)` / `composerSetText` (`host.composer`; `mode` is `'block' | 'inline' | 'prefix'`).
- **`navigate`** — `navigate` (`host.navigate`).
- **`os:clipboard`** — `osWriteClipboard`.
- **`os:dialogs`** — `osPickOpenPath` / `osPickSavePath` (the user picks, so the plugin learns exactly one path).
- **`os:open-external`** — `osOpenExternal`, http(s) URLs only.
- **`os:reveal-path`** — `osRevealPath`, paths inside the plugin's own install folder only.
- **`os:notify`** — `osNotify` (`ctx.os.notify`).

Host-only by design, never admitted to a sandboxed plugin: `cli.exec`, `profiles.configure`, filesystem, terminal and secrets RPCs, and any gateway method not in the allowlist. `host.logs`, `host.status` and `host.restartGateway` are not bridged either.

## Unsupported / by design

- **Statusbar `menuContent`** — dropped with one console warning per plugin ("statusbar menuContent is not supported in the sandbox — use render with an SDK Popover instead"). A host popover cannot paint guest UI; use `render` with an SDK `Popover` inside the frame instead.
- **`icon` given as a React component** on palette / nav items — the guest runtime strips a function-valued `icon` (the host cannot render a guest component inline) and the host draws its own glyph for sandboxed rows. Element-valued `icon`/`label`/`detail` on statusbar items still work as inline render refs.
- **`when` predicates on contributions** — a host-evaluated function over host state cannot cross the boundary; the guest warns ("… has a when predicate — not supported in the sandbox, always shown") and the contribution is always on. Gate visibility inside your own `render` instead.
- **`useI18n` / `ctx.i18n` inside the frame** sees only a catalog slice — `common`, `errors.genericFailure`, `ui.search`, `ui.pagination` (`BRIDGED_CATALOG_PATHS` in `loader.ts`) — plus the plugin's own registered locale bundles. Other host keys resolve to their key path.
- **Host DOM access** — `host.querySelector`, `host.querySelectorAll`, `host.insertBefore` throw with a hint: for the draft use `host.composer.getText()` / `insertText()` / `setText()` (capability `composer`); anything else needs an SDK hook.
- **`Streamdown`** is bundled into the frame only when the plugin source imports it; otherwise the export throws a readable error when used.
- **Toast controls** — a guest `host.notify` carries only text; `id`, `action`, `secondaryAction`, `durationMs`, `placement` are stripped (they could replace host toasts or run host code).
- **`ctx.os.openExternal`** with `file:` or custom schemes is refused (http(s) only); **`ctx.os.revealPath`** outside the plugin's install folder is refused.
- **Host calls made from inside `onDispose`** are not honoured — the realm is being torn down.

## How to regenerate

The table is produced by a throwaway script (kept out of the repo) that joins three sweep artifacts: `sdk_survey.json` — per plugin, the static survey of `plugin.js` (`imports` = SDK named imports, `host` = `host.*` members, `requests` = gateway methods passed to `host.request`, plus `ctx`, `os`, `hermesDesktop`, `document`, `window`, `when`, `other_imports`); `sandbox/sdk/results.json` — per plugin `loads` / `renders` / `action` / `gap` from driving the plugin inside the sandbox frame; and `sandbox/sdk/capabilities.json` — the `desktop_capabilities` list read from each plugin's `plugin.yaml`. Re-run the static survey over the current plugin set, re-drive the primary actions, then re-render this table (sorted by plugin name; SDK import lists longer than 12 are truncated with `… (+N)`) and update the date in the header. The *Supported surface* section is hand-maintained against `methods.ts` and `capabilities.ts`; the *Unsupported* list against `guest-runtime.js` and `loader.ts`.
